# Implementation Plan: Offline Object Detection App

**Branch**: `001-offline-object-detection` | **Date**: 2025-01-21 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification with offline object detection requirements

**Constitution Version**: 1.0.0 | **Flutter Version**: 3.x (stable) | **Dart Version**: 3.x

## Summary

Build a complete Flutter mobile application enabling users to capture photos via camera or select from gallery, then perform real-time object detection using an on-device TensorFlow Lite model. The system must operate 100% offline with detection latency <2 seconds. Visual results display bounding boxes with French labels overlaid on detected objects. Detection history persists locally with a 100-entry limit.

**Technical Approach** (from research phase): Use `tflite_flutter` with MobileNet SSD v1 (~8MB) for efficient on-device inference. Camera capture via official Flutter `camera` plugin with auto-resize to 640x640px. Gallery selection through `image_picker`. History stored using `sqflite` with thumbnail caching. Async detection in isolate to maintain 60fps UI responsiveness.

# Phase 0: Outline & Research

## Research Summary

### R1: TensorFlow Lite Model Selection

**Decision**: Use **MobileNet SSD v1** (COCO dataset, 91 object classes)

**Rationale**:
- Model size: ~8MB (under 10MB constitutional constraint)
- Inference speed: ~100-150ms on modern mobile devices (well under 2s budget)
- Accuracy: mAP ~21% (acceptable for general object detection demo)
- Wide hardware support: Compatible with Android 7.0+ and iOS 12+ through TFLite delegates
- Pre-trained availability: Readily available from TensorFlow model zoo

**Alternatives Considered**:
- **EfficientDet-Lite0**: Higher accuracy (mAP ~27%) but larger size (~10.2MB) and slower inference (~200-300ms)
- **YOLOv5n**: Faster inference (~80ms) but requires ONNX-to-TFLite conversion with potential compatibility issues
- **MobileNet SSD v2**: Similar size but marginally slower with no significant accuracy improvement

**Implementation Notes**:
- Download from: https://tfhub.dev/tensorflow/lite-model/ssd_mobilenet_v1/1/metadata/1
- Input shape: 300x300x3 (will resize 640x640 captures to 300x300 before inference)
- Output: Bounding boxes (4 coords), classes (91 COCO labels), confidence scores

### R2: Camera Plugin Best Practices

**Decision**: Use official **`camera`** plugin v0.10.x with manual permission handling

**Rationale**:
- Official Flutter team support ensures long-term compatibility
- Provides full control over camera lifecycle (initialize, preview, capture, dispose)
- Supports both Android and iOS with platform channels
- Allows custom resolution setting (set to 640x640 for consistency with detection input)

**Best Practices Applied**:
- Initialize camera in `initState()` with error handling for device availability
- Request permissions before camera initialization using `permission_handler` plugin
- Display French error messages for permission denial: "Autorisation de caméra refusée"
- Dispose camera controller in `dispose()` to prevent memory leaks
- Use `CameraController.takePicture()` for high-quality captures (not stream snapshots)

**Alternatives Considered**:
- **`image_picker`** with `source: ImageSource.camera`: Simpler API but less control over preview and resolution
- Custom platform channels: Over-engineered for this use case; official plugin sufficient

### R3: Async Inference Strategy

**Decision**: Run TFLite inference in **Dart isolate** with `compute()` function

**Rationale**:
- Isolates prevent UI thread blocking, maintaining 60fps during detection
- `compute()` provides simple API for offloading CPU-intensive work
- Memory overhead minimal (~1-2MB per isolate)
- No need for complex threading libraries (Worker, FFI) for Dart code

**Pattern**:
```dart
// In detection_service.dart
Future<List<DetectedObject>> detectObjects(Uint8List imageBytes) async {
  return await compute(_runInferenceIsolate, imageBytes);
}

static List<DetectedObject> _runInferenceIsolate(Uint8List imageBytes) {
  // Load interpreter, run inference, parse outputs
  // This runs in separate isolate
}
```

**Best Practices**:
- Load TFLite interpreter once during service initialization (not per inference)
- Pass only image bytes to isolate (not entire interpreter to avoid serialization overhead)
- Set confidence threshold to 0.5 (50%) to filter low-quality detections

### R4: Local Storage for History

**Decision**: Use **`sqflite`** for metadata + file system for thumbnails

**Rationale**:
- SQLite provides structured queries for history retrieval (ORDER BY timestamp DESC LIMIT 100)
- Storing full images in DB bloats database; file system more efficient for binary data
- `path_provider` gives cross-platform access to app documents directory
- Thumbnail generation reduces storage footprint (e.g., 200x200px JPEG ~20KB vs full image ~500KB)

**Schema Design** (see data-model.md for full details):
```sql
CREATE TABLE detection_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp INTEGER NOT NULL,
  image_path TEXT NOT NULL,
  thumbnail_path TEXT NOT NULL,
  object_count INTEGER NOT NULL
);

CREATE TABLE detected_objects (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  detection_id INTEGER NOT NULL,
  label TEXT NOT NULL,
  confidence REAL NOT NULL,
  bbox_x REAL NOT NULL,
  bbox_y REAL NOT NULL,
  bbox_width REAL NOT NULL,
  bbox_height REAL NOT NULL,
  FOREIGN KEY (detection_id) REFERENCES detection_history(id) ON DELETE CASCADE
);
```

**100-Entry Limit Strategy**:
- Query: `DELETE FROM detection_history WHERE id NOT IN (SELECT id FROM detection_history ORDER BY timestamp DESC LIMIT 100)`
- Run after each new detection insert
- Cascade delete removes associated detected_objects rows

### R5: French Localization with `intl`

**Decision**: Use **`intl`** package with ARB files for French UI strings

**Rationale**:
- Official Flutter localization approach (recommended in Flutter docs)
- ARB (Application Resource Bundle) format is JSON-based, easy to maintain
- Code generation via `flutter pub run intl_translation:generate_from_arb` creates type-safe accessors
- Future-proof for multi-language expansion (though only French required now)

**Implementation**:
```dart

  static String get cameraPermissionDenied => Intl.message(
    'Autorisation de caméra refusée',
    name: 'cameraPermissionDenied',
  );
  // ... other strings
}

// In MaterialApp
localizationsDelegates: [
  AppLocalizations.delegate,
  GlobalMaterialLocalizations.delegate,
],
supportedLocales: [Locale('fr', 'FR')],
```

**Key French Strings** (partial list):
- Button labels: "Prendre une photo", "Galerie", "Historique"
- Object labels: Auto-translated from COCO English labels via lookup table
- Error messages: "Aucun objet détecté", "Erreur de détection"
- Confidence display: "Chien 87%" (format: `${label} ${confidence}%`)

### R6: Image Preprocessing Pipeline

**Decision**: Resize to 640x640px during capture, then 300x300px before inference

**Rationale**:
- 640x640 standardizes input from camera/gallery for consistent processing
- Smaller resolution reduces inference time (image size directly impacts TFLite ops)
- 300x300 matches MobileNet SSD v1 input requirements
- Aspect ratio preserved via center crop or padding (choose crop for speed)

**Pipeline** (in `image_preprocessing_service.dart`):
1. Capture/select image (variable resolution)
2. Decode to `image` package format
3. Resize to 640x640 using bicubic interpolation (`image.copyResize`)
4. Center crop to 300x300 (or pad if using padding strategy)
5. Convert to `Uint8List` RGB format (no normalization for MobileNet SSD)
6. Pass to `tflite_flutter.Interpreter.run()`

**Performance Note**: Preprocessing adds ~50-100ms; total pipeline: capture (instant) + preprocess (100ms) + inference (150ms) + postprocess (10ms) = ~260ms ✅ under 2s budget

## Data Model (data-model.md)

- Image captured → Preprocessing → Inference → Results available → Saved to history

## Interface Contracts (contracts/detection-api.md)

See `contracts/detection-api.md` for the public API surface of `DetectionService`.

**Contract Summary**:
```dart
abstract class IDetectionService {
  /// Initialize TFLite interpreter with bundled model
  /// Throws: ModelLoadException if model file missing or corrupted
  Future<void> initialize();

  /// Run object detection on preprocessed image
  /// Input: 300x300 RGB image as Uint8List
  /// Output: List of detected objects with confidence >= 0.5
  /// Latency: <2 seconds (constitutional requirement)
  /// Throws: InferenceException on TFLite runtime error
  Future<List<DetectedObject>> detectObjects(Uint8List imageBytes);

  /// Dispose interpreter and free resources
  Future<void> dispose();
}
```

**Error Contract**:
- `ModelLoadException`: Model file not found or invalid format
- `InferenceException`: TFLite runtime error during inference
- `ImageFormatException`: Input image not in expected format (300x300 RGB)
